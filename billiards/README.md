# 🎱 Система управления бильярдным клубом

Ядро системы: столы, тарифы, сеансы с посекундной тарификацией, живой
таймер на дашборде, история сеансов, журнал событий и абстракция
управления освещением (сейчас Mock, позже — реле MOES).

Стек: **Python 3.11+, FastAPI, SQLAlchemy 2.0, SQLite, Pydantic v2**;
фронтенд — чистый HTML/CSS/JS без сборки.

---

## Установка

```bash
cd billiards
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

```bash
uvicorn app.main:app --reload
```

Откройте <http://127.0.0.1:8000> — дашборд столов.
Документация API (Swagger): <http://127.0.0.1:8000/docs>.

При первом запуске на пустой базе создаются стартовые данные:
3 стола и 2 тарифа (отключается переменной `BILLIARDS_SEED=0`).

## Структура

```
billiards/
├── app/
│   ├── main.py             # точка входа FastAPI, роутеры, обработчики ошибок
│   ├── config.py           # настройки (URL БД, сидинг)
│   ├── database.py         # engine, сессии, Base, init_db, get_db
│   ├── seed.py             # стартовые данные для пустой базы
│   ├── timeutils.py        # единая функция utcnow()
│   ├── models/             # ORM-модели: Table, Tariff, TableSession, JournalEntry
│   ├── schemas/            # Pydantic-схемы запросов/ответов
│   ├── services/           # бизнес-логика
│   │   ├── billing.py      #   расчёт стоимости (копейки, целочисленно)
│   │   ├── sessions.py     #   открытие/закрытие сеансов
│   │   ├── tables.py       #   операции со столами
│   │   ├── tariffs.py      #   операции с тарифами
│   │   ├── journal.py      #   запись событий в журнал
│   │   ├── errors.py       #   доменные ошибки (404/409)
│   │   └── lighting/       #   освещение: интерфейс + Mock (позже MOES)
│   ├── api/                # HTTP-слой (роутеры FastAPI)
│   └── static/             # фронтенд: index.html, app.js, style.css
├── tests/                  # pytest-тесты
├── requirements.txt
└── pytest.ini
```

Принципы слоёв: **api** не содержит бизнес-логики (только HTTP),
**services** не знают про HTTP, **models** — только структура данных.
Frontend работает исключительно через `/api/*` и ничего не знает об
оборудовании освещения.

## Работа с БД

- СУБД — SQLite, файл `billiards.db` в корне `billiards/` (создаётся
  автоматически при старте, в git не попадает).
- URL можно переопределить: `BILLIARDS_DATABASE_URL=sqlite:////path/to.db`.
- Таблицы создаются `Base.metadata.create_all` при старте приложения.
- Внешние ключи SQLite включены (`PRAGMA foreign_keys=ON`).
- Время хранится в UTC; API отдаёт ISO-8601 с суффиксом `Z`, браузер
  показывает локальное время.
- Деньги: цена тарифа — целые рубли в час; итоговая стоимость хранится
  **в копейках целым числом** (никаких float в БД), наружу отдаётся в рублях.
- Начать с чистой базы: остановить сервер и удалить `billiards.db`.

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/tables` | список столов |
| POST | `/api/tables` | создать стол `{"name": "..."}` |
| POST | `/api/tables/{id}/open` | открыть сеанс `{"tariff_id": N}` |
| POST | `/api/tables/{id}/close` | закрыть сеанс, вернуть итог |
| GET | `/api/dashboard` | столы + живое состояние сеансов (таймер, стоимость, свет) |
| GET | `/api/history` | закрытые сеансы (новые сверху, `?limit=`) |
| GET | `/api/journal` | журнал событий (`?limit=`) |
| GET | `/api/tariffs` | список тарифов (`?only_active=true`) |
| POST | `/api/tariffs` | создать тариф `{"name": "...", "price_per_hour": N}` |

Ошибки бизнес-логики: `404` — сущность не найдена, `409` — действие
противоречит состоянию (занятый/свободный стол, дубликат названия);
тело ответа — `{"detail": "..."}` на русском.

Стоимость сеанса пропорциональна времени: `price_per_hour` за час,
доли часа — посекундно, округление до копейки (половина — вверх).
Цена фиксируется при открытии сеанса: изменение тарифа не влияет на
уже идущие сеансы.

## Как добавить стол

Через интерфейс: вкладка «Залы» → поле «Название нового стола» →
**Добавить стол**.

Через API:

```bash
curl -X POST http://127.0.0.1:8000/api/tables \
  -H "Content-Type: application/json" \
  -d '{"name": "Стол 4"}'
```

Названия столов уникальны; дубликат вернёт `409`.

## Как добавить тариф

Через интерфейс: вкладка «Тарифы» → название и цена → **Добавить тариф**.

Через API:

```bash
curl -X POST http://127.0.0.1:8000/api/tariffs \
  -H "Content-Type: application/json" \
  -d '{"name": "Ночной", "price_per_hour": 300}'
```

Цена — целое число рублей в час, больше нуля. Названия уникальны.

## Как запустить тесты

```bash
cd billiards
python -m pytest
```

Тесты используют отдельную базу (файл во временной директории) и
отключённый сидинг — рабочая `billiards.db` не затрагивается.
Покрыто: создание стола, открытие/закрытие сеанса, запреты открыть
занятый и закрыть свободный стол, расчёт стоимости за 30 минут,
1 час и 1.5 часа, округление, снимок цены тарифа.

## Освещение (Mock → MOES)

`app/services/lighting/` — единственное место, знающее об оборудовании:

- `base.py` — интерфейс `LightingController`
  (`turn_light_on`, `turn_light_off`, `is_light_on`);
- `mock.py` — текущая реализация, хранит состояние в памяти;
- `__init__.py` — фабрика `get_lighting_controller()`.

Свет включается при открытии сеанса и гаснет при закрытии; оба события
пишутся в журнал. Для интеграции с MOES достаточно добавить класс,
реализующий `LightingController`, и вернуть его из фабрики — API и
фронтенд не изменятся.
