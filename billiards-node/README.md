# 🎱 Система управления бильярдным клубом (Node.js)

Ядро системы: столы, тарифы, сеансы с посекундной тарификацией, живой
таймер на дашборде, история сеансов, журнал событий и абстракция
управления освещением (сейчас Mock, позже — реле MOES).

Стек: **Node.js 18+, Express, better-sqlite3 (SQLite)**;
фронтенд — чистый HTML/CSS/JS без сборки.

---

## Установка

```bash
cd billiards-node
npm install
```

## Запуск

```bash
npm run dev     # разработка: авто-перезапуск при изменении файлов
npm start       # обычный запуск
```

Откройте <http://127.0.0.1:8000> — дашборд столов.
Порт меняется переменной окружения `PORT`.

При первом запуске на пустой базе создаются стартовые данные:
3 стола и 2 тарифа (отключается переменной `BILLIARDS_SEED=0`).

## Структура

```
billiards-node/
├── src/
│   ├── server.js           # точка входа: база, сидинг, listen
│   ├── app.js              # фабрика Express-приложения, обработчик ошибок
│   ├── config.js           # настройки (путь к БД, порт, сидинг)
│   ├── db.js               # подключение SQLite, схема, utcNow()
│   ├── seed.js             # стартовые данные для пустой базы
│   ├── services/           # бизнес-логика
│   │   ├── billing.js      #   расчёт стоимости (копейки, целочисленно)
│   │   ├── sessions.js     #   открытие/закрытие сеансов
│   │   ├── tables.js       #   операции со столами
│   │   ├── tariffs.js      #   операции с тарифами
│   │   ├── journal.js      #   запись событий в журнал
│   │   ├── errors.js       #   доменные ошибки (404/409)
│   │   └── lighting.js     #   освещение: Mock-контроллер (позже MOES)
│   └── routes/             # HTTP-слой (роутер API + мапперы ответов)
├── public/                 # фронтенд: index.html, app.js, style.css
├── tests/                  # тесты (node:test + supertest)
├── package.json
└── README.md
```

Принципы слоёв: **routes** не содержит бизнес-логики (только HTTP),
**services** не знают про HTTP. Frontend работает исключительно через
`/api/*` и ничего не знает об оборудовании освещения.

## Работа с БД

- СУБД — SQLite (better-sqlite3), файл `billiards.db` в корне проекта
  (создаётся автоматически при старте, в git не попадает).
- Путь можно переопределить: `BILLIARDS_DATABASE_PATH=C:\data\club.db`.
- Таблицы создаются автоматически (`CREATE TABLE IF NOT EXISTS`).
- Внешние ключи включены (`PRAGMA foreign_keys = ON`), режим WAL.
- Время хранится в UTC (ISO-8601 с суффиксом `Z`), браузер показывает
  локальное время.
- Деньги: цена тарифа — целые рубли в час; итоговая стоимость хранится
  **в копейках целым числом** (никаких float в БД), наружу отдаётся в рублях.
- Начать с чистой базы: остановить сервер и удалить `billiards.db`.

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/tables` | список столов |
| POST | `/api/tables` | создать стол `{"name": "..."}` |
| POST | `/api/tables/{id}/open` | открыть сеанс `{"tariff_id": N}` |
| POST | `/api/tables/{id}/close` | закрыть сеанс, вернуть итог |
| GET | `/api/dashboard` | столы + живое состояние сеансов (таймер, стоимость, свет) |
| GET | `/api/history` | закрытые сеансы (новые сверху, `?limit=`) |
| GET | `/api/journal` | журнал событий (`?limit=`) |
| GET | `/api/tariffs` | список тарифов (`?only_active=true`) |
| POST | `/api/tariffs` | создать тариф `{"name": "...", "price_per_hour": N}` |

Ошибки бизнес-логики: `404` — сущность не найдена, `409` — действие
противоречит состоянию (занятый/свободный стол, дубликат названия);
тело ответа — `{"detail": "..."}` на русском.

Стоимость сеанса пропорциональна времени: `price_per_hour` за час,
доли часа — посекундно, округление до копейки (половина — вверх).
Цена фиксируется при открытии сеанса: изменение тарифа не влияет на
уже идущие сеансы. Живой таймер устроен так: сервер отдаёт
`elapsed_seconds` и `current_cost`, фронтенд лишь тикает между
опросами — поэтому обновление страницы ничего не сбрасывает.

## Как добавить стол

Через интерфейс: вкладка «Залы» → поле «Название нового стола» →
**Добавить стол**.

Через API:

```bash
curl -X POST http://127.0.0.1:8000/api/tables \
  -H "Content-Type: application/json" \
  -d '{"name": "Стол 4"}'
```

Названия столов уникальны; дубликат вернёт `409`.

## Как добавить тариф

Через интерфейс: вкладка «Тарифы» → название и цена → **Добавить тариф**.

Через API:

```bash
curl -X POST http://127.0.0.1:8000/api/tariffs \
  -H "Content-Type: application/json" \
  -d '{"name": "Ночной", "price_per_hour": 300}'
```

Цена — целое число рублей в час, больше нуля. Названия уникальны.

## Как запустить тесты

```bash
npm test
```

Тесты используют базу в памяти — рабочая `billiards.db` не затрагивается.
Покрыто: создание стола, открытие/закрытие сеанса, запреты открыть
занятый и закрыть свободный стол, расчёт стоимости за 30 минут,
1 час и 1.5 часа, округление, снимок цены тарифа.

## Освещение (Mock → MOES)

`src/services/lighting.js` — единственное место, знающее об оборудовании.
Контроллер реализует три метода: `turnLightOn(tableId)`,
`turnLightOff(tableId)`, `isLightOn(tableId)`.

Свет включается при открытии сеанса и гаснет при закрытии; оба события
пишутся в журнал. Для интеграции с MOES достаточно добавить класс с теми
же методами и вернуть его из `getLightingController()` — API и фронтенд
не изменятся.
