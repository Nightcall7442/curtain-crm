# Терминальные чеки: тип оплаты и сумма за день — дизайн и план

Дата: 05.11.2026 · Статус: правка заказчика, решения — исполнителем

## 1. Что просит заказчик

Скриншот экрана «Терминальные чеки» в приложении (заметка «Terminal obshiy
summa»):

1. Под «День» (обведено красным) — **общая сумма за день**.
2. Рядом с именем сотрудника (зелёная стрелка) — **значок типа оплаты**:
   Click, Payme, Uzum, Humo, Uzcard, наличные. «Они при новом чеке
   спрашиваются — какой тип оплаты?»: тип выбирают, когда пробивают чек.

## 2. Решения

- Тип оплаты — атрибут чека, а не способ денег книги: чек в кассу не идёт
  (владелец развёл кассу и терминал), поэтому `payments.method` у чека
  остаётся `card`, а тип — отдельная колонка `payments.terminal_pay_type`
  (перечисление `terminal_pay_type`, nullable). Check: тип бывает только у
  `kind = terminal_check`.
- Новый чек без типа не создаётся (`terminalChecks.create` требует `payType`).
  Старые чеки — без типа: значка нет, в разбивке — «Без типа».
- Значки — фирменные цвета и название (Click, Payme, Uzum, HUMO, UZCARD) и
  «Наличные» с купюрой; логотипы не копируются. Цвета — общие для сайта и
  приложения (`TERMINAL_PAY_TYPE_STYLE` в `packages/shared`).
- Сумма за день — по всем чекам дня, плюс разбивка по типам (сколько чеков,
  на какую сумму). Считает сервер (`summarizeTerminalChecks` из shared) и
  отдаёт в `terminalChecks.byDay` и `terminalChecks.today` полем `summary`.

## 3. Где видно

| Место | Что меняется |
|---|---|
| Приложение, «Пробить чек» | выбор типа (6 плиток), обязательно |
| Приложение, «Терминальные чеки» (день) | под «День»: итого за день и разбивка по типам; у чека — значок рядом с именем |
| Приложение, карточка на «Работе» и плитка на главной | значок в строке чека; итого за сегодня |
| Сайт, «Касса» → терминальные чеки дня | колонка «Тип», итого и разбивка |
| Сайт, архив чеков | колонка «Тип», в Excel — колонка «Тип оплаты», итоги по типам |

## 4. План

1. **shared**: `TERMINAL_PAY_TYPES`, подписи ru/uz, `terminalPayTypeSchema`,
   `TERMINAL_PAY_TYPE_STYLE`, `summarizeTerminalChecks(rows)` — тесты
   (итог, разбивка в порядке типов, «без типа» отдельно, пустой день).
2. **db**: перечисление и колонка, check, миграция 0073.
3. **api**: `post` принимает `terminalPayType`; `entries` его отдаёт;
   `create` требует `payType`; `byDay`/`today` — `summary`; смоук
   «12. Терминал: тип оплаты» (тип сохраняется, итог и разбивка, без типа —
   отказ, тип у не-чека — отказ check-констрейнта).
4. **приложение**: `PayTypeBadge`, выбор типа в «Пробить чек», итог и
   разбивка на экране дня, значки в строках; ru/uz.
5. **сайт**: значок, колонка и итоги в «Кассе» и архиве, колонка в Excel.
6. Документация (BUSINESS_LOGIC «Терминальные чеки», API), полный прогон,
   ревью, выкат.

Приложение: на телефонах с установленным APK новое появится с новой
сборкой; версия в браузере (`/app`) обновится с выкатом сайта.
