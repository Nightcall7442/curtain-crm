# Монитор-табло «Цех» и «Установщики» — дизайн

Дата: 14.10.2026 · Статус: согласован в чате, ждёт ревью спецификации

## 1. Зачем

Руководству нужно в любой момент видеть, кто из производственных сотрудников
что делает прямо сейчас, сколько сделано и насколько выполняется план, — в
панели, в телефоне и на телевизоре в цехе. Образец — четыре макета заказчика
(«Швеи / Цех», «Установщики», мобильный поток «Главная → Швеи →
Установщики → карточка человека»). Требование: «как в референсе, но
красивее и качественнее, максимально профессионально».

### Что сказал заказчик

- Смотрят руководство (панель + приложение) **и** телевизор в цехе.
- Группы: **швеи**; **установщики вместе с карнизчиками**.
- Выдуманных данных на табло нет. Вместо отсутствующих в системе — настоящие
  показатели. Добавить в систему: **номер машинки**, **план на месяц**
  («% плана»), **дату и время установки**. Карту установок — не делать.
- ТВ открывает табло по **секретной ссылке**, без входа в панель.
- План: **норма на роль + личная поправка**, действует, пока не изменят.
  Единицы: швея — штуки (как в рейтинге), установщик и карнизчик — заказы.
- Архитектура: **отдельный серверный модуль «Табло»**, опрос раз в 20 с.
- Топ-5 — **по объёму**, планы задают **директор и админ**.

### Что считаем успехом

1. Табло «Цех» и «Установщики» в панели, в приложении и на ТВ показывают
   одни и те же числа, посчитанные одним кодом.
2. Ни одна цифра на табло не выдумана: у каждой есть источник в БД.
3. ТВ по ссылке не видит ни денег, ни клиентов, ни адресов; отозванная
   ссылка перестаёт работать сразу.
4. Табло обновляется само (≤ 20 с), переживает обрыв связи и не требует
   рук у телевизора.
5. Оформление — в языке панели (стекло, хвоя, латунь), тёмная и светлая
   схемы, без горизонтальной прокрутки на 390 px, 1536 px и 1920 px.

### Чего нет в системе и чем заменяем

| В макете | Решение |
|---|---|
| «Машинка №1» | новое поле `users.workstation` |
| «125% плана», кольца выполнения | новая таблица `work_plans` |
| «Установки сегодня 09:00…» | новое поле `orders.installation_at` |
| Прогресс текущего заказа «70%» | поштучного прогресса нет → полоса **плана месяца** с цветом темпа, у заказа — срок и «в работе 2 ч 15 мин» |
| Звёзды «4.8», «оценка клиентов» | источника нет → **% вовремя** и **качество %** из рейтинга |
| Карта установок | не делаем (решение заказчика) |
| Вкладки «Заказы», «Статистика» в приложении | не делаем: статистика — на экране человека, заказы — в существующем разделе |

## 2. Данные

Все изменения схемы — через `pnpm db:generate`, отдельная миграция на этап.

### 2.1 Номер машинки

`users.workstation smallint null`, check `workstation between 1 and 99`.
Уникальности нет: машинку делят швеи разных смен. Редактируется в
`EmployeeDialog` панели (поле показывается, если у сотрудника есть роль
`sewer`), принимается `users.update`. Выводится «Машинка №3».

### 2.2 План на месяц — `work_plans`

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | serial pk | |
| `role` | `role_enum` not null | check: `sewer`, `installer`, `cornice_installer` |
| `user_id` | int null → `users` restrict | `null` — норма роли |
| `effective_from` | date not null | check: первое число месяца |
| `target` | int null | check `target > 0`; `null` допустим только при `user_id is not null` — «с этого месяца вернуться к норме» |
| `created_by` | int not null → `users` restrict | |
| `created_at` | timestamptz default now() | |

Уникальность `(role, user_id, effective_from)` с `NULLS NOT DISTINCT` —
повторная запись в тот же месяц обновляет строку (upsert).

**Действующий план** человека `U` по роли `R` на месяц `M`
(`resolvePlan`, чистая функция в `shared` + тот же порядок в SQL):

1. последняя личная строка `(R, U)` с `effective_from <= M`;
   если её `target` не `null` — это план (источник «личный с <месяц>»);
2. иначе последняя строка нормы `(R, null)` с `effective_from <= M`
   (источник «норма роли»);
3. иначе плана нет — полоса скрыта, подпись «план не задан».

Если у человека в группе две роли (установщик и карнизчик), план — сумма
действующих планов этих ролей, выработка — сумма выработок.

Единицы — константа `PLAN_UNIT` в `shared`: `sewer → pieces`,
`installer → orders`, `cornice_installer → orders`.

Колонки «План / Сделано / %» в «Рабочих» (`users.performance`) переходят
на `work_plans`. Это заодно убирает баг: сейчас план ищется в зарплатном
KPI по роли, и всем людям одной роли достаётся цель случайного одного.
Для ролей вне `work_plans` колонка показывает «—».

### 2.3 Дата и время установки

`orders.installation_at timestamptz null`, частичный индекс
`where installation_at is not null`.

- Задаётся при переходе в `installation_assigned` вместе с исполнителем
  (необязательный параметр `installationAt` у `orders.changeStatus` и
  `orders.assign` для роли установщика) — одной транзакцией, как сейчас
  `assigneeId`.
- Меняется `orders.scheduleInstallation({ orderId, at: Date | null })`
  (`orderDispatchProcedure`): допустимо в статусах `qc_passed`,
  `pending_installation_assignment`, `installation_assigned`;
  `at >= now − 24 ч`, не дальше года вперёд. Запись в журнал действий.
- Назначенному установщику уходит уведомление нового типа
  `installation_scheduled` («Установка DH-000117: 15.10 в 10:30»), ведёт
  на заказ. Перевод — в `notificationTranslations`, ru/uz.
- Видно: карточка заказа (панель, приложение), карточка в «Работе» у
  установщика («Установка 15.10 в 10:30»), «Установки сегодня» на табло.

Поле необязательное: заказы без времени попадают в счётчик «Без времени».

## 3. Сервер

### 3.1 Чистые функции (`packages/shared/src/monitor/`)

| Функция | Вход → выход |
|---|---|
| `deriveLiveStatus` | смена (открыта/закрыта сегодня), открытая отлучка с `plannedMinutes`, открытый выезд, выходной сегодня, есть ли текущая работа, `now` → `{ status, since, until? }` |
| `isDayOffToday` | `weeklyDayOff`, одобренные интервалы выходных, день по Ташкенту → boolean |
| `resolvePlan` | строки `work_plans`, `userId`, `role`, месяц → `{ target, source, effectiveFrom } \| null` |
| `planPace` | сделано, план, прошедшие и всего рабочие дни месяца → `ahead \| on_track \| behind` |
| `installSlotState` | статус заказа, `installation_at`, идёт ли выезд по заказу, `now` → `done \| in_progress \| late \| upcoming` |
| `summarizeItems` | позиции заказа → «Окно ×2, Дверь», штуки, м² |

Правило статуса (`deriveLiveStatus`): выезд → отлучка («до 14:30» =
начало + заявленные минуты) → открытая смена моложе
`SHIFT_FORGOTTEN_AFTER_HOURS` (`working`, если есть текущая работа, иначе
`idle`) → смена закрыта сегодня (`finished`) → выходной (`day_off`) →
`absent`. Открытая смена важнее выходного: вышел в выходной — работает.

Темп: рабочие дни месяца — все дни, кроме `weeklyDayOff` человека;
`ahead`, если `% плана ≥ доля прошедших рабочих дней`, `on_track` — до
10 п.п. ниже, `behind` — ещё ниже.

Периоды — по Ташкенту: `workshopPeriodStarts` переезжает из
`reports.router.ts` в `apps/api/src/services/periods.ts` и
переиспользуется обоими.

### 3.2 `monitor.service.ts`

`buildBoard(db, { group, branchId, now })` — один согласованный снимок:

1. **Люди**: активные, с ролью группы; при `branchId` — привязанные к
   филиалу. Аватар через `storage.getUrl()`.
2. **Сегодня**: открытые/сегодняшние смены, открытые отлучки и выезды,
   выходные на сегодня.
3. **Текущая работа**:
   - швея — заказы `sewing_in_progress` с её `sewer_id`; «в работе с» —
     последняя запись истории в этот статус;
   - установщик — `installation_in_progress` с его `installer_id`, плюс
     заказ активного выезда;
   - карнизчик — `cornice_status = in_progress` с его `cornice_installer_id`.
4. **Очередь**: швея — её `pending_sewing_assignment` и `qc_failed`
   (брак помечен) по приоритету, сроку, id; установщик — его
   `installation_assigned` по `installation_at`, затем сроку. У
   карнизчиков личной очереди нет — общий счётчик.
5. **Выработка** одним запросом с `FILTER` за сегодня / неделю / месяц /
   прошлый месяц / прошлый месяц до той же даты. Определения — как в
   `rating.service.ts`: швея — штуки заказов с последним `sewing_done` в
   периоде (`greatest(sum(quantity), 1)`), установщик — заказы с последним
   `installation_done`, карнизчик — `cornice_done_at`; отменённые не
   считаются.
6. **Качество и вовремя** за месяц — из `employeeRating(…)` с
   ташкентскими границами, чтобы совпадать со страницей «Рейтинг».
7. **Планы** — `resolvePlan` на текущий и прошлый месяц.
8. **Место** за месяц — по выработке; **топ-5 прошлого месяца** — по
   выработке, при равенстве выше больший % плана, затем имя.
9. **Сводка**: выработка месяца и изменение к прошлому месяцу на ту же
   дату (%), всего людей и на смене (`working`/`idle`/`break`/`trip`),
   в среднем на человека, качество % (цех) или вовремя % (установщики),
   счётчики статусов для чипов.
10. **Только «Установщики»**: «Установки сегодня» — заказы с
    `installation_at` в сегодняшних ташкентских сутках, не отменённые,
    с `installSlotState`, номером, временем, исполнителем, адресом;
    «Без времени» — число `installation_assigned` без `installation_at`;
    карнизы — число `pending` и `in_progress`.

`buildPerson(db, { userId, now })` — карточка человека + вся очередь,
выработка по дням за 30 дней, смена сегодня (начало, конец, отлучки,
выезды), у установщиков — 8 последних фото с объектов, загруженных им.

Цель по скорости — снимок до ~150 мс на демо-данных (6–8 SQL-запросов).

| `monitor.person({ userId })` | `orderDispatchProcedure` | `NOT_FOUND`, если человек не в группе |

### 3.4 Безопасность ТВ

- Поиск ссылки по `sha256(token)` среди неотозванных; неизвестная или
  отозванная — `UNAUTHORIZED` «Ссылка недействительна». Группа должна
  быть включена в ссылке, иначе `FORBIDDEN`. Филиал берётся **из ссылки**,
  не из запроса.
- Ответ проходит `toDisplayBoard()` — отдельное преобразование на сервере,
  которое собирает новый объект из разрешённых полей: имя, фото, статус,
  машинка, номер заказа, состав, сроки, выработка, план, место, сводка,
  расписание **без адреса**. Денег, клиентов, телефонов и адресов в
  снимке нет и так; преобразование гарантирует, что их не будет и после
  будущих правок `buildBoard`.
- Потолок частоты: существующий ограничитель `/trpc/auth.` в
  `apps/api/src/index.ts` расширяется на `/trpc/display.`.
- `last_seen_at` пишется не чаще раза в минуту на ссылку.
- Фото — подписанные ссылки на час; табло перезапрашивает их с каждым
  снимком.

## 4. Веб-панель

### 4.1 Навигация

Новый пункт меню **«Табло»** (`navigation.ts`), роли — директор, админ,
менеджер. Вкладки (`SectionTabs`): «Цех» `/monitor/workshop`,
«Установщики» `/monitor/installation`, «Планы» `/monitor/plans` (директор,
админ). `/monitor` → `/monitor/workshop`.

### 4.2 Страница табло (`components/monitor/`)

1. **Шапка**: заголовок, `LiveIndicator` («онлайн · обновлено 12 с
   назад», пульсирующая точка), выбор филиала (если филиалов > 1),
   кнопка «На весь экран».
2. **Верхний ряд**: `Podium` — «Топ-5 · <прошлый месяц> · по объёму»,
   пять карточек: фото или монограмма на тонированной подложке, медали
   1–3 в латуни, номер 4–5, значение («210 шт»), % плана; первое место
   крупнее. `SummaryPanel` справа.
3. **Фильтры**: `StatusChips` со счётчиками (Все, Работают, Свободны,
   Отлучка, На выезде — только установщики, Нет на месте, Выходной),
   поиск по имени, сортировка (место, % плана, имя, машинка). Фильтр и
   сортировка — в адресе (`?status=&sort=`), чтобы ссылкой можно было
   поделиться.
4. **Сетка** `PersonCard` (5 / 4 / 3 / 2 / 1 в ряд по ширине):
   место за месяц, плашка статуса, фото или монограмма, имя, «Машинка №3»
   или «Стаж 2 года», блок текущей работы («DH-000117 · Окно ×2, Дверь ·
   срок 16.10 · в работе 2 ч 15 мин» / «На выезде с 10:12 · DH-000117» /
   «Отлучка до 14:30» / «Свободна — нет текущего заказа» / «Не
   отметилась»), `PlanBar` месяца с цветом темпа, «Сегодня / Неделя /
   Месяц», очередь (2 позиции и «+N», брак — меткой).
5. **«Установщики»**: справа `InstallSchedule` — лента «Установки
   сегодня (N)» по времени с метками ✓ / идёт / впереди / опаздывает,
   «Без времени: N» со ссылкой на `/orders?tab=installation`, «Карнизы:
   в очереди N · в работе N».
6. **`PersonDrawer`** по клику: кольцо «План месяца», столбики за 30
   дней (существующий `components/charts/Bars.tsx`), смена сегодня,
   вся очередь, у установщиков — фото; ссылка «Открыть заказ».
7. **Состояния**: скелетон по форме страницы; ошибка с «Повторить»;
   пусто — «В цехе пока нет швей: дайте сотруднику роль „Швея“»; нет
   связи дольше `MONITOR_STALE_AFTER_MS` — плашка «нет связи · данные от
   14:02», данные остаются.
8. Опрос — `refetchInterval: MONITOR_POLL_MS`, без опроса во вкладке в
   фоне.

### 4.3 «Планы» (`/monitor/plans`)

Выбор месяца. Для каждой роли плана: строка нормы (правка на месте) и
список людей — действующий план, источник («норма роли» / «личный с окт
2026»), поле личного плана (пусто = норма), сделано, %. Сохранение
действует с выбранного месяца.

### 4.4 Прочие правки панели

- `EmployeeDialog`: «Номер машинки».
- `OrderActionDialog`: дата и время установки при назначении установщика.
- Карточка заказа: «Установка 15.10, 10:30» и «Перенести» (руководство,
  менеджер).
- Настройки: `DisplayLinksManager` (директор) — список ссылок (название,
  филиал, табло, язык, «был на связи 5 мин назад», статус), создание с
  показом адреса и QR-кода (`lib/qrImage.ts`) один раз, отзыв.

### 4.5 ТВ-режим

- Публичный маршрут `/tv/[token]` вне оболочки панели; для вошедших
  руководителей — `/monitor/tv?group=…` с тем же компонентом `TvBoard`
  (данные из `monitor.board`).
- Всегда тёмная схема; разметка под 1920×1080, кегли через `clamp()` —
  читаемо на 1366 и 4K.
- Шапка: логотип, название табло, филиал, крупные часы и дата, индикатор
  связи.
- Карточки подстраиваются, чтобы все люди поместились без прокрутки; если
  не помещаются — страницы листаются каждые `TV_PAGE_MS`.
- В ссылке оба табло — смена каждые `TV_ROTATE_MS`, сверху полоса
  таймера.
- Screen Wake Lock (если браузер умеет), курсор скрывается через 3 с
  бездействия, полная перезагрузка страницы раз в 6 ч.
- Обрыв связи — последние данные и плашка «нет связи»; ссылка отозвана —
  экран «Ссылка недействительна, попросите новую у руководителя».
- Язык подписей — из ссылки.

## 5. Мобильное приложение

- **Главная** у директора, админа, менеджера: блок «Табло» — плитки
  «Швеи» и «Установщики» с «на смене 7 из 10». Те же пункты в
  `ManagementScreen`.
- **`MonitorBoardScreen`** (`group`): чипы статусов (горизонтальная
  прокрутка с `flexShrink: 0`), пьедестал лентой, список `PersonRow`
  (фото, имя, статус, машинка, текущий заказ, полоса плана, сегодня /
  неделя / месяц). Потянуть — обновить; опрос `MONITOR_POLL_MS`, пока
  экран в фокусе.
- **`MonitorPersonScreen`**: фото, статус, начало смены, текущая работа с
  «Открыть заказ» (`OrderDetail`), кольцо плана (`react-native-svg`),
  сегодня / неделя / месяц, столбики за 30 дней, очередь, у установщика —
  фото.
- **Время установки**: выбор даты и времени при назначении установщика в
  `OrderManagement` (`@react-native-community/datetimepicker`), строка в
  карточке заказа и в `OrderCard` «Работы».
- Все новые строки — ru и uz.

## 6. Проверки

- **Vitest (`shared`)**: `deriveLiveStatus` (каждая ветка приоритета,
  забытая смена, работа в выходной), `isDayOffToday`, `resolvePlan`
  (норма, личный, возврат к норме, будущий месяц не действует),
  `planPace`, `installSlotState` (граница опоздания), `summarizeItems`.
- **Vitest (`api`)**: хеширование и проверка токена; `toDisplayBoard` —
  в результате нет ключей адреса и клиента даже при их наличии на входе;
  перенос `workshopPeriodStarts` без изменения поведения.
- **Смоук на живой БД** (`scripts/smoke.ts`): снимок табло на сид-данных;
  план в SQL совпадает с `resolvePlan`; `scheduleInstallation` пишет
  время и аудит; отозванная ссылка → `UNAUTHORIZED`; менеджеру
  `monitor.board` доступен, швее — `FORBIDDEN`; ограничения новых
  таблиц (`target`, `effective_from`, `workstation`, флаги ссылки).
- **Скриншоты Playwright**: панель 1536 px (обе схемы), ТВ 1920×1080 и
  1366×768, телефон 390 px; проверка, что `scrollWidth <= clientWidth`.
- **Перед сдачей**: `pnpm typecheck`, `pnpm lint`, `pnpm test`, сборка
  панели, сборка мобильного бандла, агенты проекта `security-auditor` и
  `code-quality-auditor`.

## 7. Этапы

Каждый этап — отдельные коммиты, после каждого проверки зелёные.

1. **Данные**: миграции (`users.workstation`, `work_plans`,
   `orders.installation_at`, `display_links`, тип уведомления),
   перечисления и константы в `shared`, демо-данные.
2. **Время установки** целиком: API, панель, приложение, уведомление.
3. **Модуль `monitor`**: чистые функции, `monitor.service.ts`, процедуры
   табло, планов и ссылок, `display.board`, тесты, смоук.
4. **Панель**: табло, `PersonDrawer`, «Планы», ссылки в настройках, поле
   машинки, «План/Сделано» в «Рабочих» на `work_plans`.
5. **ТВ-режим**.
6. **Приложение**: плитки, табло, экран человека.
7. **Документация**: `BUSINESS_LOGIC.md`, `API.md`, уровни доступа в
   `ARCHITECTURE.md`.
