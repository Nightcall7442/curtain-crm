# Одна книга проводок вместо четырёх учётов денег

Деньги велись в четырёх местах: поле «предоплата» у заказа, таблица
платежей по способам, инкассации, терминальные чеки по фото и выплаты
зарплаты по дням — про одни и те же суммы, и они расходились. Решено:
единственный источник правды — таблица проводок `payments` (приход,
инкассация, выплата, возврат — одной строкой с видом и способом), а всё
производное вычисляется из неё. «Оплачено по заказу» — колонка-кэш,
которую поддерживает триггер базы на каждую проводку: приложение её не
пишет, разойтись с проводками она не может.

## Considered options

- **Пересчитывать «оплачено» в каждом запросе заказов.** Одиннадцать мест
  чтения и лёгкость забыть одно; триггер держит инвариант в одном месте.
- **Отдельная таблица на каждый вид движения** (как было). Каждый отчёт
  сводит их заново и по-своему; за полгода получилось три разных «в кассе».
- **Терминальные чеки оставить отдельным журналом.** Тогда «принято
  картой» и «чеков пробито» — два числа про одно, и норма дня продавцов
  считается не по деньгам.

## Consequences

- Закупки остаются документом (цена × количество, категория) и в книгу
  проводок не входят: касса читает их как расход напрямую. Способа оплаты у
  закупки нет — все считаются наличными из кассы; когда появятся закупки со
  счёта, потребуется поле способа.
- Возврат — обычная проводка с видом «возврат»; «оплачено» не может уйти
  ниже нуля — это проверяет база, а не только код.
- Поле «предоплата» из интерфейса руководства исчезло: оплаченное меняют
  только проводкой (приход или возврат), не правкой числа.
