# Развёртывание на Railway

Топология: **один домен**. Панель принимает весь трафик, а `/trpc`, `/files`
и `/health` пересылает во внутренний адрес API. Так сохраняется схема одного
источника — браузер и телефон ходят туда же, откуда пришла страница, и CORS
в проде не участвует.

Причина не в удобстве: Railway привязывает домен к ОДНОМУ сервису и не умеет
разводить запросы по путям, как это делает `Caddyfile` на своём сервере.
Роль прокси приходится отдать самой панели.

Плата за это записана честно: **пока лежит панель, лежит и мобильное
приложение** — его запросы идут через неё. Для мастерской с двумя десятками
сотрудников это приемлемо; когда перестанет быть приемлемым, API выносится
на `api.<домен>`, а `NEXT_PUBLIC_API_URL` при сборке панели меняется с `/trpc`
на полный адрес. Код к этому готов, менять придётся только переменные.

Развёртывание на своём сервере (`docker-compose.prod.yml` + Caddy) остаётся
рабочим и не удалено — это два независимых способа, а не замена.

```
                  ┌──────────────────────────────┐
   Браузер ─────► │  web    crm.pardabozor.uz        │
   Телефон ─────► │  Next 15                      │
                  │    /trpc/*  ──┐               │
                  │    /files/* ──┤ rewrites      │
                  │    /health  ──┘               │
                  └───────────────┼──────────────┘
                                  ▼  приватная сеть Railway (IPv6)
                  ┌──────────────────────────────┐
                  │  api    api.railway.internal  │
                  │  Hono + tRPC, том /app/storage│
                  └───────────────┼──────────────┘
                                  ▼
                  ┌──────────────────────────────┐
                  │  Postgres (плагин Railway)    │
                  └──────────────────────────────┘
```

---

## 1. Сервисы

В проекте Railway создаются три сервиса:

| Имя        | Что это                | Источник                            |
| ---------- | ---------------------- | ----------------------------------- |
| `Postgres` | база                   | плагин Railway (`Add → Database`)   |
| `api`      | сервер API             | этот репозиторий, `railway.api.json` |
| `web`      | веб-панель             | этот репозиторий, `railway.web.json` |

Имя сервиса API должно быть именно **`api`** — от него зависит внутренний
адрес `api.railway.internal`, который прописывается панели. Переименуете —
поправьте `API_INTERNAL_URL`.

Для `api` и `web` в настройках сервиса указывается:

- **Root Directory** — пусто (корень репозитория). Оба образа собираются из
  корня: иначе в контекст сборки не попадут `packages/shared` и `packages/db`,
  подключённые как воркспейс-зависимости.
- **Config as code** — `railway.api.json` и `railway.web.json` соответственно.
  В них уже заданы путь к Dockerfile, команда запуска и проверка живости.

## 2. Переменные сервиса `api`

Обязательны только две — `DATABASE_URL` и `JWT_SECRET`; у остального есть
значения по умолчанию, но в проде их надо задать явно.

```
DATABASE_URL           = ${{Postgres.DATABASE_URL}}
JWT_SECRET             = <48 случайных байт, см. ниже>
NODE_ENV               = production
HOST                   = ::
TRUST_PROXY_HEADERS    = true
CORS_ORIGINS           = https://crm.pardabozor.uz
STORAGE_DRIVER         = disk
STORAGE_DISK_PATH      = /app/storage
STORAGE_PUBLIC_BASE_URL= https://crm.pardabozor.uz/files
MAX_UPLOAD_SIZE_MB     = 15
ACCESS_TOKEN_TTL_MINUTES = 15
REFRESH_TOKEN_TTL_DAYS   = 30
```

Секрет:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

Этим же секретом подписываются ссылки на файлы, поэтому его смена разом
обесценит и выданные токены, и выданные ссылки. Это нормально и обратимо
только повторным входом сотрудников.

### `HOST = ::` — не опечатка

Приватная сеть Railway работает **только по IPv6**. Процесс, слушающий
`0.0.0.0`, принимает лишь IPv4 и для панели остаётся недоступным: запрос к
`api.railway.internal` уходит в никуда, а в логах панели видно только таймаут
шлюза. `::` слушает IPv6 и, за счёт двойного стека, продолжает принимать IPv4.

Значение по умолчанию в коде — `0.0.0.0`, потому что для `docker compose`
оно верное. Здесь его переопределяем.

### `TRUST_PROXY_HEADERS = true`

Адрес клиента приходит заголовком `X-Forwarded-For` от пограничного узла
Railway. Без этого флага ограничитель попыток входа считал бы весь трафик
одним клиентом и заблокировал бы всю мастерскую после нескольких неудачных
паролей.

### Том для файлов

`Settings → Volumes → Add volume`, путь монтирования — **`/app/storage`**.

Без тома фотографии заказов, аватары и голосовые комментарии исчезнут при
первом же передеплое, а в базе останутся ключи на несуществующие файлы —
битые картинки в карточках заказов задним числом не чинятся.

## 3. Переменные сервиса `web`

```
NODE_ENV         = production
API_INTERNAL_URL = http://${{api.RAILWAY_PRIVATE_DOMAIN}}:3000
```

`NEXT_PUBLIC_API_URL` **не задаётся**: при `NODE_ENV=production` сборка сама
подставляет относительный `/trpc`, и браузер обращается на тот же домен,
откуда пришла страница.

### Почему смена `API_INTERNAL_URL` требует пересборки

`rewrites()` вычисляется на этапе `next build` — Next записывает готовые
адреса в `routes-manifest.json` и при старте берёт их оттуда. Переменная
обязана быть видна во время сборки, а её правка вступает в силу только после
нового деплоя, а не после перезапуска. Railway отдаёт переменные и сборке,
и рантайму, поэтому достаточно задать её один раз — но помнить про это надо.

Порт `3000` в адресе — это `PORT` сервиса API. Railway молча подставляет
службе СВОЙ случайный `PORT` (например 8080), поэтому обоим сервисам
переменная задана явно: `PORT=3000` у `api`, `PORT=3001` у `web` — иначе
панель стучится на 3000, а API слушает 8080, и всё отвечает 502.

Ещё одно свойство Dockerfile-сборок Railway: переменная сервиса видна
сборке ТОЛЬКО через объявленный `ARG`. Для `API_INTERNAL_URL` он объявлен
в `apps/web/Dockerfile`; без него панель молча собирается без rewrites.

## 4. Первый запуск

**Миграции выполняются сами** при каждом старте контейнера API — это
зашито в `CMD` его Dockerfile. Запускать их руками не нужно и, главное,
неоткуда: база доступна только из приватной сети Railway, поэтому
`railway run ... db:migrate` с машины разработчика падает с
`ENOTFOUND postgres.railway.internal`. (`preDeployCommand` в
`railway.json` не подошёл: config-as-code объявлен устаревшим и на
практике игнорируется — проверено на живом деплое.)

Сид включается флагом: задайте сервису `api` переменную **`RUN_SEED=true`**,
передеплойте, дождитесь в логах строки «Сидирование завершено» и верните
`RUN_SEED=false`. Сид идемпотентен — случайный повторный прогон ничего
не ломает.

Переменные сида читаются оттуда же, где заданы, — задайте их сервису `api`
перед запуском и удалите после:

```
SEED_CEO_NAME     = Директор
SEED_CEO_PHONE    = +998901234567
SEED_CEO_PASSWORD = <временный, сменить сразу после входа>
SEED_BRANCH_NAME  = Цех №1
SEED_BRANCH_LAT   = 41.311081
SEED_BRANCH_LON   = 69.240562
SEED_PAYROLL_EFFECTIVE_FROM = 2026-01-01
```

Координаты филиала — настоящие координаты цеха: по ним сервер решает,
засчитать отметку о приходе или отказать. Ошибётесь на квартал — сотрудники
не смогут открыть смену, стоя на рабочем месте.

`drizzle-kit` лежит в devDependencies пакета `@curtain-crm/db`, а образ API
собирается без `--prod`, поэтому обе команды работают внутри контейнера
без отдельного образа для миграций.

## 5. Домен

Домен привязывается к сервису **`web`**, не к `api`. У `api` публичного
домена быть не должно вовсе: он доступен только по приватной сети, и это
не настройка, а свойство топологии.

1. `web → Settings → Networking → Custom Domain`, ввести `crm.pardabozor.uz`.
2. Railway покажет цель для CNAME. Прописать её у регистратора.
3. Дождаться выдачи сертификата — обычно минуты, иногда до часа.

### Почему поддомен, а не `pardabozor.uz`

Голый домен (апекс) по стандарту DNS не принимает CNAME — в его зоне уже
обязаны быть записи SOA и NS, а CNAME не терпит соседей. Railway же выдаёт
именно CNAME-цель.

Обойти это можно только средствами DNS-провайдера: ALIAS/ANAME у
регистратора либо CNAME-flattening у Cloudflare. У регистраторов зоны `.uz`
такой записи обычно нет, поэтому надёжный путь — перевести NS домена на
Cloudflare (бесплатно) и там поставить CNAME на апекс.

Отдельный довод за поддомен: `pardabozor.uz` остаётся свободен под сайт
мастерской. CRM — внутренний инструмент, и отдавать ей главный адрес,
по которому будут приходить клиенты, незачем.

Если решите всё же занять апекс — поменяйте адрес во всех местах раздела 4
(`CORS_ORIGINS`, `STORAGE_PUBLIC_BASE_URL`) и в `app.json` мобильного
приложения. Ничего, кроме этих значений, от имени хоста не зависит.

После привязки поправьте на сервисе `api` два значения на боевой домен:
`CORS_ORIGINS` и `STORAGE_PUBLIC_BASE_URL`. Второе особенно важно: по нему
собираются подписанные ссылки на файлы, и с адресом по умолчанию
(`http://localhost:3000/files`) фотографии не откроются ни у кого.

## 6. Проверка после деплоя

```bash
# API жив и отвечает через панель
curl -s https://crm.pardabozor.uz/health

# tRPC отвечает (401 — это правильный ответ без токена)
curl -s -o /dev/null -w "%{http_code}\n" \
  "https://crm.pardabozor.uz/trpc/auth.me?batch=1&input=%7B%220%22%3A%7B%22json%22%3Anull%7D%7D"

# Панель отдаёт экран входа
curl -s -o /dev/null -w "%{http_code}\n" https://crm.pardabozor.uz/login
```

Ожидается `{"ok":true,...}`, затем `401`, затем `200`. Если `/health` отдаёт
502 или таймаут, а сама панель открывается — почти наверняка `HOST` на API
остался `0.0.0.0` (см. раздел 2).

Дальше — войти под директором, сменить пароль, завести филиалы и сотрудников.

## 7. Мобильное приложение

В `apps/mobile/app.json` в `extra.apiUrl` укажите `https://crm.pardabozor.uz/trpc`
и соберите приложение заново. В разработке адрес по-прежнему выводится из
хоста Metro-сервера, боевое значение читается только из собранного конфига.

## 8. Что осталось на вас

- **Резервные копии базы.** Railway делает снимки на платных тарифах;
  проверьте, что они включены. Снимок базы не покрывает том с файлами.
- **Резервные копии файлов.** Том Railway отдельно не выгружается —
  используйте `pnpm --filter @curtain-crm/api backup` по расписанию либо
  переведите хранилище на S3 (`STORAGE_DRIVER=s3`, драйвер уже написан).
- **Один экземпляр каждого сервиса.** `numReplicas: 1` в конфигурациях стоит
  осознанно: ограничитель попыток входа держит счётчики в памяти процесса и
  при двух экземплярах считал бы порознь, а том Railway к двум экземплярам
  всё равно не подключается.
